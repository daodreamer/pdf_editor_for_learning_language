# 阶段 8 Windows 交付与本机验收

日期：2026-10-15。范围：用户授权以 goal 模式完成阶段 8；macOS 构建、运行、Metal 与打包按要求延期。本轮交付 Windows 实现和未签名便携候选包，不等同于双平台或正式公开发行审批完成。

## 实现内容

- 阅读视图在首次打开文档后创建，之后保留控件实例，由页面模型继续虚拟化。首次视口上报通过事件循环执行，避免初始化重入。PDFium、调度、坐标、保存格式和导出算法保持原有职责。
- 导航和编辑工具栏可换行；640×480 窗口对按钮边界及阅读区域高度有断言。小窗口使用带提示和可访问名称的线性图标；笔色、粗细工具随画笔模式出现。图标为原创 Qt Quick Shapes / PathSvg 路径，没有增加 QtSvg 或第三方图标依赖。
- 快捷键说明覆盖所有已交付工具；Windows 使用 Ctrl；macOS 组合键分支仍待实机核实。保存状态与导出状态独立显示，补充“导出成功后保存失败”真实文件故障回归，避免旧导出消息遮挡保存错误。
- `package-windows.ps1/.py` 生成 Qt/QML、PDFium、Noto 字体及 MSVC CRT 的便携目录、源码快照、文件清单、ZIP 和 SHA-256 文件。构建后记录产品输入与 EXE 散列，打包拒绝过期源码/二进制及检测到的 sanitizer/非 Release 配置，核对 PDFium 和字体副本。输出拒绝覆盖，也不能放入源码子目录。
- `validate-windows-package.py` 校验文件及源码快照，从独立副本清理 SDK 环境运行实际产品，核查观察到的 Qt 动态库/插件来源，再加入测试专用文件运行六个功能套件。CI 配置接入构建、QML lint、打包、校验和产物归档；本轮未推送，未取得远程 CI 运行证据。

## 环境与启动 A/B

Windows 11 Pro 10.0.26200，Intel Core Ultra 7 265K（20 核/20 逻辑处理器），RAM 50873622528 bytes；设备包含 NVIDIA RTX 5070 和 Intel Graphics，驱动见 `environment.json`。Qt 6.8.3、PDFium 157.0.8100.0、MSVC 19.51、C++20 Release。测试实际图形 API 为 D3D11（枚举 4），Qt 报告屏幕 160 Hz；不据此声称系统实际呈现固定 160 FPS。

受控 A 为提前创建阅读控件，B 为延迟创建。`startup-control-difference.json` 逐项核对产品源码/字体，仅 documentLoader.active 初值不同（比较时规范化行尾）。两个实际源码树和二进制分别散列；交错 AB/BA，每组 3 次预热 + 30 次新进程，系统缓存保留。

| 热启动交互代理（ms） | A 提前创建 | B 延迟创建 |
| --- | ---: | ---: |
| 外部中位数 | 411.76 | 395.61 |
| 外部 P95 | 428.83 | 424.28 |
| main 内部中位数 | 388.83 | 373.79 |
| main 内部 P95 | 405.77 | 396.23 |

中位数实测降低约 16.16 ms / 3.9%；P95 差距较小，不能夸大为稳定尾延迟收益。外部口径含进程启动、日志传输和驱动等待，内部口径为 main 至首帧后合成 F6 回执，均不是硬件输入到显示延迟。**热启动 300 ms 目标仍未达到**。冷启动、系统 scanout、带文档的端到端进程启动未测。早期 `startup-control/`、`startup-lazy/` 有多处实现/环境差异，只保留诊断价值，不当作本次受控 A/B。

## 阅读、导航和缩放

样本为已有原创合成扫描 PDF：800 页、839214902 bytes，SHA-256 `be2b255dbc4aa8a776248ebd03a795006cd450014ab554864efd6edf36b5e2c8`。散列读取预热 OS 缓存；不是 JPEG/JPX 真实大型教材。每轮独立进程，原始帧间隔来自渲染线程 `frameSwapped` 单调时钟，nearest-rank 分位，不是系统实际呈现。

| 轨迹 | 重复次数 | 结果 |
| --- | --- | --- |
| 纯滚动：约 1 视口/s，向下 60 s 后返回 60 s | 5×120 s | P95 6.43–16.74 ms，P99 6.73–18.17 ms；5 次退出码均为 0，见 scrolling-final |
| 混合压力约 500 px/s，含远跳、缩放与一次资源重建 | 5×65 s | P95 6.45–17.02 ms，P99 7.40–19.72 ms；全部功能/资源断言通过，详见 baseline-final |
| 8 视口/s，每 2 s 反向 | 5×30 s | P95 6.47–6.50 ms，P99 10.63–11.13 ms；停止输入后偏差为 0，全部可见目标就绪，见 fast-converged |
| 首页/中间/末页及固定种子 50 次跳页 | 5 轮 | 共 250 次动作全部完成，可见区域预算目标就绪代理中位数 143.0 ms、最大 159.0 ms；不是屏幕呈现时间，见 navigation-final |
| 50%/100%/200%/400%，20 轮共 80 次切换 | 5 轮 | 共 400 次动作全部完成，可见区域预算目标就绪代理中位数 18.0 ms、最大 61.0 ms，见 zoom-final |

纯滚动与混合轨迹均有轮次波动，保留全部成功轮与窗口 active 状态，不选最好一轮宣称稳定达标。混合轨迹每秒采样的预览覆盖均值为 92.31%，最小值 0：采样紧接远跳动作，存在时序偏差，**不等于 7.69% 墙钟时间空白，也不是逐帧实际像素覆盖率**。图像/纹理计数证明实际解码和显示路径在工作，但尚不能据此给出系统呈现层的完整可见覆盖比例。

纯滚动的 1 Hz 预览覆盖采样均值 1.0000、最小值 1.0000，仍不替代逐帧实际呈现观测。完整结果见 final-performance-overview.json。

首屏高清和动作完成按真实 viewport 范围内全部相交页面的预算目标分辨率检查；高倍缩放仍可因预算降低背景分辨率，不承诺 400% 原生扫描精度。`*_frame_callback_proxy_ms` 只是就绪之后观察到的排队 Qt 回调，不能证明该回调对应的帧已包含新位图。

快速轨迹最初两次诊断失败保存在 `fast-final/`、`fast-lag-diagnostic/`。原四分之一屏距离守卫在常规速度相当于约 267 ms，高速仅约 31 ms；实测失败偏差 195.44 px，按当时速度等效 45.75 ms 输入距离。测试现结合速度选择四个 16 ms 间隔的有界距离容差（测试选择，不是 Qt 保证）；实际速度、阈值与倍数记在 profile_policy 事件，并记录最大偏差；不是改渲染逻辑或把距离等效时间当作硬件输入延迟。失败没有计入成功轮的分位或删除。

## 30 分钟组合压力与关闭资源

`workflow-30min/` 成功运行 1801.20 s（含启动/关闭），执行 118 次大/小文档切换、59 次恢复快照比较、120 次新增真实笔迹，经正常自动保存/切换提交；全部恢复内容一致。CPU 页面预算 128 MiB，GPU 受管像素预算 64 MiB，活跃页面峰值 4。

GPU 共 295 条采样、3 条错误，保留原记录；缺失不按零处理。CPU/GPU 系统口径与受管预算分开，互相重叠的内存不能简单相加。关闭后分配器、Qt 与驱动仍可保留内存；该结果不证明所有库不存在泄漏。

长测 Qt 提交间隔 P95/P99 为 16.49/18.07 ms，最大 246.96 ms，包含多次主动 hide/release/show、打开与保存恢复；这是组合压力，不是普通滚动达标证明。前段并行过诊断构建和一次无窗口存储探针，启用了系统 GPU 采样；窗口 active 状态与默认测试字体也有记录，不能与最终统一产品字体的基线混作 A/B。原长测源码经过反向恢复后逐文件核对运行前 manifest 的全部 42 个 SHA-256，并保存原二进制；`source-reconstruction.json` 明确记录重建方法，没有拿后续修改冒充原源码。

## 候选包与发行边界

本轮候选输出路径为 `build/packages/Langlern-0.1.0-windows-x64-candidate/`，ZIP 与 SHA-256 文件在相邻路径；实际文件清单、包散列与运行结果分别见包内 manifest.json、相邻 .sha256 及 package-validation/summary.json。用户操作、更新和数据保留见 [WINDOWS_PACKAGE.md](WINDOWS_PACKAGE.md)。包内 `source.zip` 含应用、测试和基准源码，不含私有 PDF、结果目录、Python/MuPDF 或 SDK 工具二进制。

排除不需要的 DXC/DXIL，D3D11 编译器来自 Windows SDK Redist 并附完整条款。Qt 实际 DLL 与可匹配供应商 SPDX 的关联、许可声明、vendor SHA1 比对保存在 `licenses/deployed-binaries.json`。所有文件另有 SHA-256，完整 Qt 供应商 SBOM/通知、PDFium 通知、字体 OFL 与微软 redist 入口随包。通知超集不代表所有 SDK 组件都被部署；不匹配项保持可见。

公开发布前仍需处理：发行主体的微软许可资格与最终分发方式、依赖安全更新、干净 Windows 环境、真实系统 IME/触控板/手写笔与物理跨屏验证、签名策略。macOS 全部实机工作按用户要求延期。开发机清理 SDK 路径不是干净 VM，不把候选包描述成已完成整体许可审批。

## 后续建议

Windows 本机已具备阅读、练习、保存恢复和导出的完整 MVP 路径；优先安排用户实际教材与真实输入设备体验，继续定位窗口 show/D3D11 初始化和帧节奏波动，补足冷启动与系统呈现观测。真实 500 MiB–2 GiB 压缩教材、低内存设备和复杂文字体系仍未覆盖；阶段 3 的 P3-START-1 / P3-SAMPLE-1 / P3-INPUT-1 不因本轮候选交付自动关闭。坐标、缓存和关闭资源已有进一步证据，完整进程/驱动内存归因仍需保留。


## 本轮环境边界与后续验收

当前 Windows Sandbox 可执行文件不存在，CIM 显示 Containers-DisposableClientVM 的 InstallState=2（未启用），没有检测到可用 VM 管理命令。因此“干净 Windows 离线部署”尚未执行，不能用本机清理 SDK 路径代替。用户随后明确确认“就在当前本机环境中就行”，因此本轮以本机独立目录验证为部署验收范围，不等待或启用 VM，不重启主机。Mac 平台延期已有用户授权。真实系统 IME、物理输入设备、跨屏和正式发布方式仍按上文如实标记，不能把自动化模型测试冒充人工系统验收。

最终大文件复测：CPU 首图 10.595 ms、身份/编辑就绪 4368.869 ms、显式保存 61.474 ms、导出 22895.957 ms，输出 845821740 bytes，1984 次 GUI 心跳。单次诊断，源文件与导出后的独立回读另存 final-export；时间口径沿用阶段 7，不能与不同环境的旧单次数据推导优化收益。

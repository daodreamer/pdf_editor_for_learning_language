# 性能工程与验收方案

日期：2026-10-15。状态：方法与门槛保留；阶段 0 初始测量见 PHASE0_REPORT.md，阶段 1 Windows 启动和空闲样本见 PHASE1_REPORT.md。阶段 2 单页和句柄回归见 PHASE2_REPORT.md。其余指标不能因已有局部数据而视为通过。

## 阶段 1 实际采样口径

`benchmarks/run-startup.py` 以 `time.monotonic_ns()` 记录每个新进程启动请求，经管道接收 `interactive_proxy` 时记录外部时间；程序以同一 QElapsedTimer 记录 QApplication ready、engine ready、QML ready、show 请求/返回、首个 frameSwapped 和合成 F6 响应。外部时间包含创建进程和日志/管道调度开销，内部时间不包含 main 以前的加载，两者分列。`interactive_proxy` 只证明首帧提交后 Qt 主线程能处理合成快捷键，**不是**系统键盘往返或实际呈现，也不能代替本文目标定义的完整 window_interactive 验收。

固定 3 次丢弃预热 + 30 次新进程，warm OS/Qt cache，无截图/大量 QSG 日志，Release；逐次保留 JSONL 日志、源码与可执行文件 SHA-256、实际 build_type、Qt/API 和 DPR，P95 使用 nearest-rank。冷启动必须另用受控重启/缓存策略采样；本次不称冷启动通过。窗口 1120×760 逻辑像素，默认 DPR 1.5；当前 Windows 构建显式选择 D3D11。

`benchmarks/check-shell-idle.py` 对无参数正常程序等待 2 秒后做一次 5 秒进程 CPU 时间差和末点 RSS/private 采样，并检查加载模块中没有 PDFium。0 CPU 增量只表示系统采样粒度内未见增加，不证明绝对零开销；RSS/private 不是自有缓存或 GPU 显存。采样结束强制终止脚本自建子进程，正常关窗由交互测试覆盖。程序无应用自建持续轮询由代码审查和该单次样本共同支持；不推导所有设备/长期空闲表现。

阶段 1 启动目标若未达到，保留差距，并用 show 前后日志继续定位窗口/字体/图形初始化；不得改成只计算 QML ready 来宣布达标。阶段 8 补完整可交互、冷启动、实际呈现和多设备复测。

模块与线程见 [ARCHITECTURE.md](ARCHITECTURE.md)，实施阶段见 [ROADMAP.md](ROADMAP.md)。目标是让大型扫描教材的阅读、输入和手写保持低资源消耗与即时响应，不能由技术栈直接推断实际速度。

## 1. 指标定义与证据等级

所有应用内时间使用单调时钟，跨线程使用相同进程时间基准。操作系统工具的时钟需要同步标记；不能直接相减不同起点的计时器。

| 指标 | 起止点 / 统计 | 注意事项 |
| --- | --- | --- |
| 启动到窗口可交互 | 外部启动请求 `process_launch` → 首帧及输入往返均完成的 `window_interactive` | 包含进程加载；`main_enter` 到窗口只作为内部子指标 |
| 文档打开 | `open_requested` → 页数和首个所需页面信息已可用 | 不等于首屏可见 |
| 首屏预览可见 | `open_requested` → 包含真实目标页预览的帧被提交/呈现 | 空白窗口、占位符或纹理创建不算完成 |
| 首屏目标清晰度 | 同一起点 → 当前视口所需目标分辨率图块全部进入显示帧 | 与预览分开；记录缩放、DPR、覆盖区域和档位 |
| 缩放即时反馈 | 输入到旧纹理按新变换显示 | 另记稳定后高清替换时间 |
| 帧时间 | 连续有效帧的时间间隔，报告 P50/P95/P99/max 和超过刷新预算比例 | 平均 FPS 不能掩盖尾延迟 |
| UI 响应 | 事件到主线程处理及对应画面提交 | 定时器心跳只是停顿代理，不能替代真实输入延迟 |
| 文字/笔迹延迟 | 输入事件 → 对应答案/笔迹进入显示帧 | 应用级统计不含设备扫描和屏幕发光延迟 |
| worker 延迟 | 排队等待、页面加载、渲染、文本、导出分别计时 | 不能把排队耗时算成解码或漏掉 |
| 取消有效性 | 取消请求 → 丢弃结果 / worker 开始服务新目标 | 区分队列删除、结果丢弃与底层真正暂停 |
| CPU 内存 | 进程私有提交/物理驻留/峰值及应用各预算 | 不与缓存大小、GPU 显存混用 |
| GPU 使用 | 系统工具分配/驻留；受管纹理字节单独记录为估算 | Apple Silicon 统一内存不可简单与进程内存相加 |
| CPU 利用率 | 每进程 CPU 时间 / 墙钟时间，注明是否按逻辑核归一 | 空闲、滚动和导出分别报告 |
| 缓存命中率 | CPU/GPU 各自命中 / 有效查找；精确与降级命中分开 | 预加载命中不能混成用户请求命中 |
| 浪费与背压 | 过期计算时间、丢弃结果字节、上传次数/字节、队列长度 | 判断取消与清晰化策略是否有效 |
| 保存 | 修订提交 → 对应修订原子提交完成 | 同时记录最大未保存窗口和失败 |

证据分三级：内部标记（图像 ready / 同步 / 提交）、系统合成/呈现时间、外部高帧率拍摄的实际显示。`frameSwapped` 或提交回调并非屏幕发光时间；缺少系统呈现工具时标为“提交代理”，不得声称已测端到端延迟。

## 2. 初始目标与阶段门槛

下表是初始目标和拟定门槛，**均不是测量结果**。阶段 0 先收集基线并确认工具口径；阶段 3 起用固定参考配置判断回归。门槛需要修改时先写明原因及影响，不能通过改口径掩盖退化。

| 项目 | 初始目标 / 判定 | 首次适用 |
| --- | --- | --- |
| 热启动可交互 | 争取 P95 < 300 ms | 阶段 1 测，阶段 8 汇总 |
| 冷启动可交互 | 争取 < 800 ms；冷样本不足仅报告分布，不声称 P95 | 阶段 1 / 8 |
| 60 Hz 常规滚动 | 目标帧预算 16.67 ms；初拟 P95 ≤ 16.67 ms、P99 ≤ 33.33 ms，同时报告超预算比例 | 阶段 3 / 8 |
| 120/144 Hz | 分别以 8.33/6.94 ms 为目标预算，报告实际达到程度 | 阶段 8，需相应设备 |
| 输入/纹理反馈 | 目标 P95 在两个刷新周期内提交，且无应用造成的 > 100 ms 连续 UI 停顿 | 阶段 3/5/6；阶段 0 仅观察 |
| 首屏与高清 | 每类真实样本建立 P50/P95、峰值和像素覆盖基线，阶段 0 后提出数值目标 | 阶段 0 起，当前不随意承诺秒数 |
| 资源预算 | 应用可控驻留不得无界或持续超过配置；单次预留、替换峰值有账可查 | 阶段 3 |
| 正确性 | 错页、过期结果回填、丢答案、覆盖原文件、资源越界为零容忍 | 所有适用阶段 |

帧间隔受刷新同步、平台工具精度影响，报告真实分布和测量误差；不能在 60 Hz 屏幕上用平均值宣称实现高刷新率。首次高清渲染可比即时滚动慢，两者分别验收。

数值目标未达到时如实报告“未达标”及瓶颈。阶段 0 的通过不要求最终 FPS/启动达标，但需要技术可行性和风险证据；阶段 8 若目标未达成，需保留差距及发布限制，不能直接宣布全面达标。

## 3. 设备、环境与构建控制

每个结果绑定环境清单：

- OS 版本、CPU、逻辑核、RAM、GPU、驱动、存储型号与可用空间。
- Windows x64 或 macOS arm64，屏幕分辨率、刷新率、缩放/DPR、多显示器状态。
- 电源模式、是否接电、温度/降频、后台负载及虚拟机/远程桌面情况。
- 源码提交或源码散列、Qt 版本/模块、PDFium 提交/构建配置、编译器与 SDK。
- Release 或 RelWithDebInfo、LTO 等优化、日志和诊断开关、实际 RHI 后端。
- 文件所在介质、样本 SHA-256、是否预读/预热、OS 页缓存策略、应用缓存状态。
- 窗口尺寸、缩放轨迹、缓存/图块/预加载配置与随机种子。

正确性可在 Debug 运行，正式性能使用固定的优化构建。带图形验证层、QML profiler、sanitizer 或大量日志的结果另存，不能与无诊断基线混比。先测采集器本身的开销，日志批量写入，不逐帧强制 flush。

参考设备至少各有一台 Windows x64 与 Apple Silicon 真机；具体型号由阶段 0 盘点确定，不预填不存在的机器。低内存及高刷新率设备作为补充。CI 的虚拟 GPU / 离屏数据用于回归辅助，不代表用户真机 GPU 体验。

## 4. 测试 PDF 样本矩阵

每个样本的 manifest 记录来源/许可、生成脚本版本、字节数、页数、页面尺寸分布、扫描像素、压缩、文字层、旋转/裁剪、特殊字体和 SHA-256。下表是目标覆盖，不是已有文件。

| 类别 | 目标规模 / 内容 | 用途 |
| --- | --- | --- |
| T1 小型文本 | 约 10–30 页，中英混排、跨行、组合字符、连字 | 正确性、启动与文本索引 |
| T2 常规扫描教材 | 约 200–500 页，100–500 MB，混合灰度/彩色 | 日常连续阅读与预加载 |
| T3 大型扫描教材 | 约 800–1500 页，500 MB–2 GB | 首页、队列、缓存与长期滚动 |
| T4 超大单页 | 高像素图片、大页面、复杂透明/矢量 | 内部解压、峰值、分块和取消 |
| T5 几何异常 | 混合尺寸、非零/负边界、CropBox、四向旋转、非默认 UserUnit | 坐标和显示/导出一致性 |
| T6 故障输入 | 截断、坏交叉引用、受密码保护、权限受限 | 错误处理、无挂死 |
| T7 大量标注 | 固定种子的答案与笔迹，分不同数量/点数档位 | 几何、命中、历史、保存与导出 |
| T8 额外尺寸边界 | 跨文件接口偏移上限附近的样本，条件允许时执行 | 检查 Windows 大小/偏移，不计为普遍无限支持 |

公开小样本可提交 fixtures，真实教材经授权后仅本地存放。确定性生成 PDF 可用于几何/调度实验，但必须标“合成样本”；不要用重复空白页或填充文件体积代表真实扫描教材性能。生成器本身的依赖和许可证也要记录。

## 5. 标准实验轨迹

所有轨迹优先使用进程外驱动或可复现的应用级命令，并保留少量真实鼠标/触控板检查。应用级重放不覆盖 OS 输入链路，需注明证据边界。窗口、DPR 和轨迹坐标在 run manifest 中固定。

| 编号 | 步骤 | 观察指标 |
| --- | --- | --- |
| B01 启动 | 无文档启动；另测带文档路径启动；等可交互后正常退出 | 冷/热、外部启动、main、窗口、初始化拆分 |
| B02 首页 | 清应用页面缓存，打开 T1/T2/T3/T4，等预览及当前视口高清 | 打开、首像素、高清、读取字节、峰值 |
| B03 常规滚动 | 适应页宽，按约 1 视口/秒向下 60 秒再返回，实际轨迹落盘 | P95/P99、未覆盖区域、命中率、内存 |
| B04 快速反向 | 约 8 视口/秒，每 2 秒反向，持续 30 秒 | 过期任务、等待、浪费、回填错误、worker 重新服务 |
| B05 导航 | 固定种子选择首页/中间/末页及 50 个跳页目标 | 请求到预览/高清、节点数与队列有界 |
| B06 缩放 | 围绕固定页面锚点在 50%/100%/200%/400% 切换，重复 20 轮 | 旧纹理反馈、高清稳定时间、漂移、上传峰值 |
| B07 输入 | 固定位置输入拉丁文、中文 IME、多行，移动/撤销/重做 | 事件到提交、预编辑正确性、PDF 渲染次数 |
| B08 手写 | 固定种子笔迹，分 10²/10³/10⁴ 采样点，颜色粗细/擦除/历史 | 增量更新、几何成本、延迟、历史预算 |
| B09 资源压力 | 降低配置预算、反复滚动/缩放、最小化重显、切换屏幕 | 淘汰、降级、纹理重建、受管峰值 |
| B10 保存与故障 | 编辑后保存，提交前/中/后终止进程，重启；模拟无权限/满空间 | 最后有效修订、恢复时间、错误状态 |
| B11 导出 | T1/T3/T5 加中英文字和笔迹，导出期间继续编辑 | UI 响应、worker 独占、时间、峰值、文件正确性 |
| B12 长期运行 | T3 连续运行滚动/缩放/标注 30 分钟，含至少 50 次切换文档 | 稳态内存、句柄、队列、过期结果与停顿 |

B03/B04 的可见内容就绪率以视口有效页面区域为分母，排除页间空白；预览和目标清晰度覆盖分别报告。不允许用空白滚动画面获得高 FPS。

## 6. 冷热启动、重复次数与统计

热启动：每次为新应用进程，先做至少一次明确不计入结果的预热；OS 文件缓存保留，应用缓存策略固定。热启动不指在同一进程反复显示窗口。

冷启动：优先使用明确记录的系统重启后首次启动；若使用 OS 支持的缓存控制方法，记录方法和权限。不把关闭应用、清页面缓存或等待几秒称为冷启动。无法控制缓存时标“OS 缓存未知”。

常规计时默认 3 次预热、30 次正式运行，每次重置约定状态。复杂交互轨迹至少 5 次完整运行，保留逐帧数据；冷启动初期至少 5 个独立冷样本，报告每次值和范围，不能从 5 个样本声称稳定 P99。正式冷启动 P95 分析需扩大到至少 30 个独立样本，并注明尾分位仍不稳定。

启动/打开的 P95/P99 是**跨运行**分布，帧时间的 P95/P99 是**每条轨迹内帧**分布，两者分开。30 次运行不用于可靠推断 P99；需要 P99 的任务延迟至少采集 1000 个同类有效事件，并报告数量和相关性限制。帧时间每轮单独统计，再报告各轮范围，不仅合并所有帧掩盖某轮严重退化。

分位数先采用 nearest-rank，记录算法。超时、失败、崩溃必须单列，不能作为离群值删除；成功运行延迟与整体失败率并列。只有有证据的环境干扰可剔除，并保留原始样本和剔除原因。A/B 比较交错运行、配置唯一变化，避免温度或缓存顺序偏差。

## 7. 采集工具与落地顺序

工具清单是拟采用方案，实际版本、可用性及权限由阶段 0 核对。先用低依赖方案形成数据，再按具体瓶颈添加工具。

| 层次 | 工具 / 实现 | 用途与限制 |
| --- | --- | --- |
| 通用内部计时 | `std::chrono::steady_clock` / QElapsedTimer、统一事件 sink | 排队、解码、缓存、保存及输入里程碑；不等于系统呈现 |
| 功能和微基准 | Qt Test + CTest，自定义固定种子 benchmark | 坐标、命中、缓存、真实引擎；记录依赖，不默认再加性能库 |
| Qt Quick | QML Profiler、QSG 计时/后端日志 | 查主线程绑定、节点同步与 GPU 路径；诊断开关与正式基线分离 |
| Windows | Windows Performance Recorder / Analyzer、进程内存计数、按需 PresentMon | 进程启动、线程、I/O、合成呈现；核实工具版本与图形路径 |
| macOS | Instruments Time Profiler / Allocations / Metal System Trace，Activity Monitor 辅助 | CPU、分配、图形；Apple Silicon 共享内存不可重复计算 |
| 图形诊断 | D3D / Metal 验证层，按需 GPU 调试器 | 仅故障定位，不用调试层 FPS 代表发布性能 |
| 外部延迟 | 高帧率相机或同等可核验方案 | 仅设备可用时测输入到屏幕；否则明确未测 |
| 汇总 | Python 标准库或已有可用工具，输出 CSV/JSON/Markdown | 不为初始报告引入数据平台依赖 |

Qt 官方记录了 RHI 选择、`QSG_INFO` 和图形诊断开关 [Qt Scene Graph 渲染器](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph-renderer.html)。这些开关的实际效果须按固定 Qt 版本验证，不能只看环境变量就断定真实 GPU 后端。

## 8. 埋点、数据结构和存储

建议低成本事件：`main_enter`、`window_frame_submitted`、`window_interactive`、`open_requested`、`document_opened`、`page_info_ready`、`demand_replaced`、`job_enqueued/start/end`、`result_rejected`、`image_ready`、`texture_uploaded`、`preview_frame_submitted`、`sharp_frame_submitted`、`save_committed`、`export_finished`。

事件应包含单调时间、线程、会话、请求、页面、图块、分辨率、输入事件/修订关联 ID。实际呈现时间从系统工具额外关联；应用日志不能自行填写未观察到的 `presented`。

建议目录（运行后生成，非本次已存在文件）：

```text
benchmarks/results/<run-id>/
  manifest.json          # 环境、构建、输入、配置、工具与时钟基准
  events.jsonl           # 原始事件
  frames.csv             # 每帧时间及覆盖度
  resources.csv          # 内存、纹理、句柄、队列、CPU 采样
  summary.json           # 指标、分位数算法、失败/超时计数
  report.md              # 结果、比较、限制和下一步
```

没有真实数据时结果表写“未测”，不填看似合理的数字。日志默认不记录文件正文、用户答案或完整私人路径；样本通过 ID/散列关联。大型 trace 本地或构建产物留存，仓库保存可审查摘要及获取方式，避免把教材和隐私答案上传 CI。

## 9. 内存预算实验

容量单位统一使用 bytes / MiB / GiB。阶段 0 根据设备记录候选预算，禁止在正式报告中将候选参数描述为最优值。应用配置至少包含：

- CPU 页面/预览和缩略图预算。
- GPU 纹理受管预算与每帧上传上限。
- worker 单任务像素上限、在途字节及待上传字节上限。
- 文本快照、标注历史预算和预加载/排队上限。

以实际 `stride × height` 计算 CPU 图像，唯一底层存储只计一次；纹理估算考虑格式、图块、mip 与替换重叠，并注明驱动/atlas 开销未必可见。需要分配前预留，避免“已分配后发现超额”。

首先计算可见区域的工作集和最低预览成本，再确定可见 pin 上限；预算不足时缩小分辨率或减少预加载。不要在不可满足的预算下无限保留旧图。PDFium 内部可能按整张图片解码，单图块位图预算不能代表完整进程峰值。

对 B12 比较每轮同状态采样及静置后值、句柄、引用和纹理待回收量。分配器保留高水位不直接等于泄漏；持续增长时用分配 trace 定位。应用自有资源关闭后计数应归零，GPU 与 OS 内存释放延迟单独说明。

## 10. 正确性伴随验收

任何性能结论须同时满足：

- 页码、图块、颜色、alpha、旋转和裁剪正确，没有旧会话结果回填。
- 预览最终被当前目标分辨率替换，覆盖率可核实；没有跳过渲染以提高帧率。
- 输入和笔迹在 PDF 坐标中稳定，纯变换误差 ≤ 1e-6 页面单位；设备整数舍入允许 1 像素。
- IME 预编辑/提交正确，undo/redo 模型往返一致，历史淘汰不影响现有答案。
- 保存失败、导出失败不会写成功状态；恢复校验最后有效修订，原 PDF 散列不变。
- 导出在两个独立查看器检查文字可见与可提取、笔迹和页面几何；不把引擎自渲染作为唯一证据。

金图和像素阈值按引擎/平台/字体固定，抗锯齿差异不能无理由放宽，也不能要求不同平台所有像素完全相同。采用几何、内容提取和人工图像检查互相补充。

## 11. CI 与性能回归策略

阶段 0/1 建立 Windows/macOS 构建、CTest 和小型真实 PDF 检查，阶段 3 加调度/缓存/坐标回归；阶段 7 加故障与导出；阶段 8 形成真机完整报告。

普通 CI runner 共享负载不稳定：PR 上优先硬性检查资源计数、队列有界、坐标/导出正确性；耗时指标先作告警，不将一次抖动定性为回归。固定真机可用后执行 B01–B12，基线与硬件、依赖和配置绑定。

候选回归告警为中位数或 P95 比基线恶化超过 10%，且超出测得噪声范围；随后以同环境 A/B 复测确认。这是待校准规则，不是已建立的自动门禁。所有基线更新记录原因，不能用覆盖旧数据清除退化。

本方案描述测试入口，不创建定时任务或自动化调度；执行频率在具备 runner 和实施需求后另行配置。

4. 实际 D3D11 / Metal 后端证据分别归档，无法测得的系统 GPU 显存写“不可用”，并附受管纹理估算。
5. 首份基线、工具误差和环境限制；为首页和资源预算提出下一阶段待确认目标。

阶段 0 已执行 Windows 真实教材和合成大文件基线，权威结果见 [PHASE0_REPORT.md](PHASE0_REPORT.md) 与 `benchmarks/results/phase0-20261015/baseline/`。已采集 worker 打开/渲染/清理耗时及进程 RSS；冷启动、可交互时间、实际呈现帧时间 P95/P99、GPU 显存、缓存命中率仍未测，不据此宣称达到产品性能目标。


## 阶段 2 实际口径（2026-10-15）

正式 worker 的 `pdf_opened`、`pdf_frame` 使用每次需求内 QElapsedTimer 单调时钟；`worker_ms` 是需求执行至当前图像产生的累计时间，含打开/页面加载/预览等此前工作，不是单独 PDFium render 时长，也不是屏幕呈现时间。session/revision/page（零基）和 preview 标记区分文件、请求与清晰度；不记录路径或正文。

`tests/shell` 对每次关闭等待 `documentClosed`，核对实际 RAII 文档/页/位图计数归零；50 次循环在第 1/10/25/50 次用 GetProcessMemoryInfo 记录 working set/private/peak working set。该计数不包括 PDFium 内部缓存或 OS 句柄，CPU 进程内存不等于缓存预算；Qt/GPU 与分配器可保留高水位，短循环和小幅增长不能证明长期无泄漏。场景图纹理的 bytes_estimate 是图像尺寸估算，不是实测 GPU 显存。

本轮用 839,214,902 bytes / 800 页原创 raw 灰度图像 PDF 验证首页和末页按需加载。它不覆盖 JPEG/JPX 等真实扫描教材解码，也不验证连续阅读帧率。默认回归的单次首页 worker 预览/目标累计时间为 3.719/9.789 ms，末页 12.680/18.994 ms；OS 文件缓存已热且样本数为 1，不能称 P95、冷启动或正式性能基线。早期同样本打开曾测到 375.805 ms、末页累计约 2.9 s，保留于 budget-fixed.log，不能择优后宣称稳定性能。

证据根目录 `benchmarks/results/phase2-20261015/`，环境/散列/运行步骤见 PHASE2_REPORT。尚未新增冷启动、可交互完整验收、实际帧时间分布或 GPU 显存测量；阶段 1 的启动统计保持历史结果，不能用于代表已接入 PDFium 的阶段 2。


## 阶段 3 连续阅读测量方法

`benchmarks/run-reading.py` 调用真实 Qt Quick/D3D11 的 reading_tests 轨迹；输入文件先散列，明确预热系统文件缓存。`--seconds 60 --repeat 5` 用于重复轨迹，`--seconds 1800 --repeat 1` 用于连续 30 分钟压力。目录以 CreateNew/不存在方式创建，拒绝覆盖结果。只记录散列、资源、页码与时间，不保存文档正文。

最终轨迹由 frameSwapped 的 GUI queued 回调推进下一帧，按单调时钟实际经过时间移动约 500 逻辑 px/s（资源重建后的单次追赶最多计 200 ms），每 11 秒远跳并反向、19 秒切换缩放，61 秒隐藏/释放/重显窗口。每秒记录当前页、缩放、活跃节点数、CPU 图像、GPU 像素估算、缓存计数和 Windows working set/private。逐帧数据保存在 `.frames.json`，窗口激活/可见状态、实际与模型滚动偏移及资源在 JSONL，逐次引擎/纹理事件在 test log。邻域与 pin 一并计费；低预算有独立确定性测试。

帧时间直接在渲染线程 `frameSwapped` 事件采集 `steady_clock` 时间戳，读取时短暂锁定复制；GUI queued 连接会混入主线程投递等待，不用其间隔充当渲染帧分布。该事件仍是 Qt 提交代理，不是系统实际 scanout，也不是 OS 输入到屏幕延迟。首次图像/目标交付使用单调时钟，从开始打开计时；其后 GUI 收到的首个 frameSwapped 作为首像素/目标提交代理。分位为 nearest-rank。

缓存精确命中率=exactHits/lookups，降档复用率=degradedHits/lookups；lookups 为可见范围/分辨率改变或显式跳页，含重新回到已有页的需求，不含每帧重复读取 model role。renderJobs 包含邻页预加载，不能作为分母。GPU 无独立 LRU 命中率，本阶段记录纹理创建事件和驻留估算，不伪造 GPU 命中百分比。

`sample-gpu-windows.ps1` 可对指定 reading_tests PID 每约 5 秒读取 Windows GPU Process Memory 的 Dedicated/Shared/Total Committed，实例按 PID 过滤并汇总；缺失计数为 null/错误记录，不当作零。它是系统报告的进程 GPU 内存，包含驱动和 Qt 开销，不等于模型像素预算。计数器采样有额外开销，启用情况写入报告；采样可能漏过短峰值。

30 分钟轨迹和最终数值见 PHASE3_REPORT.md。开发中旧 qWait、8 ms timer 驱动/GUI queued 间隔数据仅作诊断，保留原始结果，不能与最终渲染事件数据混为 A/B 性能提升。


初期 8 ms PreciseTimer 轨迹确实出现同一运行从约 500 px/s 降至约 257 px/s；这直接证明输入驱动节奏改变，但不足以确定具体 OS/Qt 原因。timer 轨迹保留功能/预算验证价值，帧分布不能直接当作最终固定速度滚动基线。最终帧驱动的 raw frame 仍包含一次 hide/release/show；故最长间隔可能来自有意重建资源，不得把整体 max 无条件称为普通滚动卡顿或把它悄悄删除。

通知优化控制 A 与最终 B 使用相同帧驱动、65 秒、前台激活、设备/构建类型/预算及固定输入；A 恢复每次滚动发全 role 通知，B 仅在几何或图像变化时发对应通知。A 的完整源码快照在 `.tools/phase3-control-source/`，runner 的 `--source-root` 只指定散列来源，绝不把当前源码冒作旧二进制源码。A 单轮与 B 多轮只能作初步比较，不能证明稳定性能收益。

阶段 3 最终 Windows 数值见 [PHASE3_REPORT.md](PHASE3_REPORT.md)：5×65 s 固定速度轨迹 P95 6.47–16.20 ms、P99 7.50–17.26 ms；长压力及系统 GPU 计数单列。3+30 热启动外部交互代理 P95 396.10 ms，未达 300 ms 目标；P3-START-1 等任务明确保留。macOS 和冷启动未验证。

## 阶段 4 文字选择诊断

复现：SDK PATH 下运行 `build/windows/text_tests.exe boundedTextCost`。构造 65536 个不可变原生字符位置，单调 QElapsedTimer 记录 100 次扩选的 GUI 命中与字符串生成合计时间。此人工阵列用于限定数据规模与计费，真实 PDF 读取另由套件其余测试覆盖，不冒充引擎提取性能。结果保存在 `benchmarks/results/phase4-20261015/accepted-text-tests.log`：4194336 bytes 快照、314.949 ms/100 次，约 3.15 ms/次；单次诊断，不是帧分位或输入到屏幕延迟，也无 A/B 提升结论。

真实超限页含 3×30000 字符文本对象，worker 的文字任务约 25.283 ms 后返回明确上限错误。该时间来自本轮单次 worker 时钟，不代表一般文档。快照 16 MiB 和单页字符上限不限制 PDFium 解析内部分配，图像、文字、选区几何与系统进程/GPU 口径分别报告。选区操作不增加 renderJobs 的行为断言、双 DPI 像素差检查和场景图后端证据见 [PHASE4_REPORT.md](PHASE4_REPORT.md)。本轮没有重新测量启动、长期滚动帧分布或系统 GPU 峰值；阶段 3 待办保留。

## 阶段 5 标注验证口径

新增 `annotation_tests` 检查已输入文字、原始锚点与局部方向、模型事务、IME preedit/commit/cancel、文字局部撤销、GUI 移动后 Ctrl+Z、焦点切换和活跃范围。`renderJobs` 在稳定页面编辑前后保持相同，证明该操作没有提交新的 PDF 渲染；不据此声称键入到屏幕延迟或 60 FPS 已达标。

高 DPI 使用独立进程 `QT_SCALE_FACTOR=2`，日志记录窗口逻辑尺寸及实际 DPR，当前为 3；它不模拟真实跨屏移动。GUI 投影以数据中原始锚点为准，允许 ≤1 设备像素的误差，排除最初鼠标点击整数舍入，纯原始坐标矩阵往返 <1e-6 页面单位，真实旋转/CropBox/UserUnit 样本角点检查 <0.001 原始单位。这些测试不替代原生高亮的设备像素差检查，也不代表 PDF 导出位置已验证。

没有新增 A/B 优化或长期性能结论，没有重测启动、滚动帧时间、系统进程/GPU 峰值；阶段 3 待办继续保留。实际运行文件和边界见 [PHASE5_REPORT.md](PHASE5_REPORT.md)。


## 阶段 6 长笔迹测量

`benchmarks/run-ink.py --run benchmarks/results/<新目录> --repeat 3` 在真实 Qt Quick/D3D11 窗口注入 8192 次 mouse move，每 64 次 qWait(8)，坐标限制在实际可见页内；记录源码/二进制/样本散列、每次事件处理时间与单调时钟、渲染线程 frameSwapped 间隔、Windows 结束 working set/private 和进程生命周期 peak working set。日志与 JSON 是复现证据；不采集系统 GPU 内存或 private 峰值。

handler_ms 仅测 sendEvent 内 GUI 处理，未涵盖几何同步与屏幕呈现；frameSwapped 是 Qt 提交代理，包含突发输入和测试等待间隔，不能当作硬件输入到屏幕延迟或稳定 60 FPS 证明。高 DPI 独立进程 QT_SCALE_FACTOR=2 的实际 DPR=3，系统可能缩短窗口逻辑高度，测试按可见边界生成轨迹，不能用裁剪外事件冒充有效书写。

实际三次独立进程结果、设备、口径、原始路径及限制见 [PHASE6_REPORT.md](PHASE6_REPORT.md)。本阶段没有 A/B 性能提升结论，没有重测启动或 30 分钟滚动，阶段 3 待办继续保留。历史 16 MiB 是包含容器 capacity 的受管数据容量，不是进程/GPU 内存上限。


## 阶段 7 保存与导出测量

`storage_tests` 使用 QElapsedTimer 测量导出请求至 GUI 成功回调，另用 GUI 定时器记录事件循环心跳；不是帧率或硬件输入延迟。默认小样本覆盖八种旋转/UserUnit 组合；`LANGLERN_LARGE_PDF` 启用大文件用例，产物集中到 `LANGLERN_PHASE7_ARTIFACT_DIR` 指向的新运行目录。测试失败保留文件，不覆盖旧证据。

800 页、839214902 bytes 原创合成扫描样本，Windows Release 单次结果：CPU 首页图像回调 62.146 ms，全内容身份与恢复就绪 8078.679 ms，显式保存回调 51.290 ms，实际 PDF 导出 24573.139 ms，输出 845821740 bytes。前两者分别是工作线程图像到 GUI 与工作区可编辑时间；没有显示设备呈现计时。导出包括两次源内容 SHA-256、字体准备、PDF 写入与回读，不能当作纯保存 API 时间。样本不代表真实压缩教材，不据单次运行推断优化提升。

标准八页真实窗口证据运行导出 258.516 ms，27 次 GUI 心跳；大文件打开至导出处理 3638 次心跳。定时器请求间隔 1 ms 不保证实际 1 ms；只证明事件循环仍在处理。未新增进程/GPU 峰值或帧时间分布测量，阶段 3 性能待办保留。完整设备、依赖、真实原始路径、验证及限制见 [PHASE7_REPORT.md](PHASE7_REPORT.md)。

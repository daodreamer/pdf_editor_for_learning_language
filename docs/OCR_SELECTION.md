# 离线 OCR、选文与朗读

## 使用方式

- 自动模式：单击空白输入、单次按住拖动书写；双击左键的第二次按住拖动选择页面文字。双击不拖动选整词。点击已识别原文仍可查词，等待系统双击间隔后打开，以兼容双击手势。
- 点读模式：直接拖选原生/OCR 文字；可见扫描页按需识别，全书其余页由后台队列在空闲时识别（见下节）。
- 文本框内部：TextEdit 保持普通左键拖选和键盘选择，格式工具条加入复制、朗读；操作不转移编辑焦点、不改选区、不提交 IME。
- 页面选区：浮层提供复制、朗读、查词；Ctrl/Command+C 保持有效。
- “··· → OCR 与朗读设置”：法语（默认）、英语、简中、法英组合；可显式识别整页或框选区域。开关“空闲时识别全书扫描页”（默认开），进度“已识别 x / y 页”（含跳过的原生文字页），暂停/继续，“清除本书识别结果”。区域识别后自动选中该区域文字；随后点击区域外会重新取得该页文字层。
- 朗读使用系统实际可用的本地声音，可设置语言、声音和 0.5–2 倍语速，支持暂停/继续/停止。缺少声音时明确提示，短选文不自动猜语言，长选文分段播放，不静默截断。更换文档/关闭窗口停止朗读。

## 实现与预算

PDFium 唯一专用线程先读取原生字符；原生文字存在时优先使用。空文字扫描页或显式 OCR 请求在该线程生成不含应用答案/笔迹的底图，宽度目标 2400、最多 32 MiB，仍受 8192 边长约束。独立低优先级 OCR 线程接收不可变 QImage，灰度识别得到符号边界、词间空格、换行和阅读顺序。结果转换回归一化页面显示坐标，共用 TextSelection/SelectionItem；缩放不重新识别。

单页最多 65536 个字符，页面文字总预算沿用 16 MiB。OCR 待执行图像使用单槽替换，任一时刻最多一个执行任务和一个待办快照。会话和语言修订双重检查拒绝旧结果。Tesseract 识别阶段使用 ETEXT_DESC 的取消回调和 30 秒期限；初始化、版面分析和第三方内部调用不能保证立即打断。正常关闭异步等待 PDF/OCR 两线程结束后退出，析构仅作兜底。模型通过 QFile 读取，覆盖 Windows 中文路径。

结果缓存位于应用 CacheLocation/ocr-v1，隔离验收时位于 LANGLERN_WORKSPACE_DIR/ocr-v1。键包含原 PDF SHA-256、页码、Tesseract 版本、模型内容散列、语言、输入尺寸和识别区域。原子写入 JSON，单文件上限 8 MiB，最多 256 条/128 MiB，按修改时间淘汰；读取失败或无效时重识别。缓存是可删除的学习辅助结果，不写回 PDF，不混入答案快照或 PDF 导出。2026-11-27 起 `ocr-v1` 只保存区域识别结果和无法建立书目存储时（例如 PDF 校验失败）的整页结果；整页结果改存到下节的按书存储。

## 全书后台识别（2026-11-27）

**调度**：`OcrBookQueue`（UI 线程纯逻辑）记录每页状态（未知 / 原生 / 完成 / 进行中 / 本会话失败）。下一页取离当前页最近的未知页，距离相同时先取后一页。`ShellState::schedule` 的顺序为：可见页预览与清晰化 → 原生文字 → 前台 OCR（可见页、选区、显式整页或区域）→ 非可见页清晰化 → 页尺寸元数据 → 后台。后台请求同时满足以下条件才会发出：

- 开关开启，没有暂停；
- 书目存储已读完，练习存储已就绪；
- 没有前台 OCR 在途或待办；
- 没有导出、扫描优化或文件切换；
- 距最近一次滚动、缩放、跳页、选文、编辑或打开文档已满 `OcrBookConfig::idleMs`（1500 ms）。

**一次一页**：每一页在 PDFium 线程上只占一个任务（`PdfRequest::ocrProbe`）。先读原生字符，有字就只记为原生页，不生成底图；没有字才在同一任务里生成 2400 px 底图（上限 32 MiB）。下一页要等本页在 OCR 线程识别结束后才发出，所以任一时刻最多有一张后台底图。

**让出**：
- 用户一旦有交互，就不再开始新的一页。
- 滚动和缩放会使正在 PDFium 线程渲染的后台底图失效：渲染无法中断，完成后丢弃结果，该页重新排队。
- 已进入 Tesseract 的后台页不会因滚动取消（它在另一个低优先级线程上运行，A/B 结果见下）。但前台 OCR、暂停、关闭开关、更换语言或文档、清除存储都会通过 `ETEXT_DESC` 取消回调中止它，该页放回队列。
- 连续 3 页失败（例如缺模型）后停止并显示原因，点“继续”会重试。

**存储**：`AppLocalDataLocation/ocr-books-v1/<PDF SHA-256>/<profile>/`；隔离验收时为 `LANGLERN_WORKSPACE_DIR/ocr-books-v1`。不放在 CacheLocation，因为 macOS 会清理缓存目录，而全书识别要几分钟。

- **profile**：SHA-256(格式版本、Tesseract 版本、语言串、各模型文件 SHA-256、管线参数 `w2400|gray8|psm-auto|ppi250|lstm`)。语言或模型一变，路径就变，旧结果不会被读到。
- **`manifest.json`**：原子写入，内容为格式版本、PDF 身份、profile、语言、页数、Tesseract 版本、创建时间和最近使用时间。
- **每页一个 `pages/NNNNN.lpo`**（小端二进制，QSaveFile 原子写入）：
  - 头：`LPOC` magic、版本、类型（OCR 或原生）、页码、字符数
  - 区域（4 个 double）和归一化显示坐标到 PDF 页面坐标的变换（6 个 double）
  - 每个字符 13 字节：u32 码点、4×u16 归一化框（1/65535）、可见标志
  - 尾部为整文件 SHA-256
- **原生页**：先缓存在内存里，第一张 OCR 页建立目录后才写盘。全是文字层的文档不会留下任何文件。
- **损坏重建**：校验失败的页文件被删除并重新排队；清单损坏或与页数、profile 不符时，删除整个 profile 重建。
- **容量**：单书（含所有 profile）上限 256 MiB，超出时拒写、停止并提示；所有书合计上限 1 GiB，打开文档或写入时按最近使用时间淘汰其他书，从不淘汰当前书；每本书最多保留 2 个 profile（例如法语和法英组合）。这套规则与 `ocr-v1` 的 256 条 LRU 无关。
- **清理入口**：“清除本书识别结果”会删除本书所有 profile。
- **范围**：存储只是学习辅助数据，不写入 PDF，不进入答案快照和 PDF 导出。

**复用**：前台整页 OCR 的结果同样写入书目存储。已识别页在需要文字时（点读可见页、选文）由 OCR 线程直接读文件，不再经 PDFium 渲染底图。“重新识别当前页”会跳过存储并覆盖旧结果。后台结果只交给已加载、仍缺 OCR 文字的活动页，其余页面不占文字内存预算。

**生命周期**：
- 切换或关闭文档、更换语言时，递增书目令牌和会话号，取消后台页，作废 OCR 修订号。旧结果既不写盘，也不计入新文档。
- 退出时沿用原有顺序：作废 OCR → 退出 OCR 线程 → 关闭 PDFium 线程 → 两个线程都结束后关闭窗口。

**只读接口（供以后的全文搜索使用，搜索本身未实现）**：`OcrBookReader(root, identity, profile)` 可在任意线程创建实例。
- `pages()`、`nativePages()`：列出已识别页和原生页；
- `page(n)`：返回已校验的字符、归一化框和 `displayToPdf`；
- `text(n)`：返回单页纯文本；
- `forEachPage(visit)`：遍历全书。
- `ShellState::ocrBookReader()` 返回当前文档、当前语言对应的实例。

**默认开启**：主要用户读的就是大型扫描教材，全书识别也是之后全文搜索的前提；识别完全离线，只在闲置时、一次一页、在低优先级线程上运行。代价是首次打开一本书的几分钟内会多占一个核心，以及几 MB 磁盘。笔记本用电池时会多耗电，开关和暂停按钮可以随时关掉。测试程序设置了 `LANGLERN_NO_BACKGROUND_OCR=1`，只有 `ocrbook` 套件会打开它。`LANGLERN_OCR_BOOK_IDLE_MS` 只供基准测试的最坏情况使用。

锁定来源、源码 tarball/模型 SHA-256、模型提交及通知文件散列见 `third_party/ocr.lock.json`。`tools/bootstrap-ocr.py` 只在开发准备/构建时获取固定产物；应用没有网络下载逻辑。

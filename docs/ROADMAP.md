日期：2026-10-15。状态：阶段 0 本机技术验证、阶段 1 Windows 应用外壳已交付，跨平台检查保留待办；阶段 2 Windows 单页阅读已交付，阶段 3–8 未实施。实际结果见 [PHASE0_REPORT.md](PHASE0_REPORT.md)、[PHASE1_REPORT.md](PHASE1_REPORT.md)、[PHASE2_REPORT.md](PHASE2_REPORT.md)。

## 1. 执行原则与依赖

**最新授权覆盖原停止位置**：用户明确要求使用 goal 模式完成阶段 2，并将全部 macOS 实机检查推迟到整个项目完成后。阶段 2 按 Windows 范围交付；不把 macOS 待验收作为本轮阻断，也不宣称双平台通过。原阶段 0/1 停止要求仅为历史授权范围。阶段 0 字体导出等风险按既有报告保留，不在本阶段提前实现阶段 7。

本轮只完成阶段 2，结束后不自动进入阶段 3。

阶段顺序保持用户要求。坐标系统、字体导出和恢复方案的可行性验证前移到阶段 0，完整实现仍放在阶段 5/7，避免基础架构成型后才发现无法准确导出。性能埋点从阶段 0/1 开始，阶段 8 汇总而不是首次测试。

```mermaid
flowchart LR
    P0[0 技术验证] --> P1[1 应用外壳]
    P1 --> P2[2 文档与单页]
    P2 --> P3[3 连续阅读与缓存]
    P3 --> P4[4 原生文字选择]
    P4 --> P5[5 文字答案]
    P5 --> P6[6 手写与历史]
    P6 --> P7[7 保存恢复与导出]
    P7 --> P8[8 优化与打包]
```

图中表示推荐交付顺序。实际能力依赖为：阶段 4/5 均依赖阶段 3 的页面几何与异步服务；阶段 5 的输入仲裁需要阶段 4 的文字命中结果；阶段 6 复用阶段 5 的坐标和标注模型；阶段 7 依赖文字与笔迹的稳定数据契约及阶段 0 的导出验证。

每个阶段都必须有一个可构建、可启动或可执行测试的增量。前一阶段产物保持可用，不用大量不可运行的占位接口表示进度。发现门槛未通过时修复或明确报告阻断，不把未验证平台计为通过。

## 2. 通用完成定义

- 使用固定源码提交、依赖版本、构建配置，记录实际命令和退出状态。
- 本阶段目标有真实运行或测试证据，失败和跳过项可追踪。
- 核心线程、坐标及原始文件保护约束不被破坏。
- 按本阶段适用范围更新架构、性能基线、编译说明和已知限制。
- Windows x64 和 macOS arm64 分别记录结果。只有一个平台可用时可交付该平台的部分结果，但双平台阶段状态仍为未完成。
- 阶段完成不等于整个 MVP 完成，原型通过不等于所有性能目标已达到。

## 3. 阶段 0：技术风险与最小验证原型

**目标**：证实固定技术栈能在目标平台构建，并完成真实 PDF 从后台渲染到场景图显示、坐标往返和文字/笔迹导出的最短链路；查清许可和分发路径。

**依赖条件**：三份规划文档就绪；具备可用工具链及对应平台访问条件。当前不假定 Qt、PDFium、编译器、CMake 或 macOS 设备已安装/可用。

### 3.2 最小原型实施方案

两个 probe 均使用同一套最小 adapter 和 worker，避免原型之间复制不同的生命周期处理。它们仅保留技术验证所需界面和参数。

**`phase0_pdf_probe`，命令行/无图形主入口**：

- 输入本地 PDF 路径、页码、目标像素或 DPI、输出目录与配置。
- worker 内初始化 PDFium，打开文件，记录页数/首页元信息，渲染指定页并输出图像和 JSONL 事件。
- 有文字的样本提取字符及页面坐标；无文字层明确报告空结果。
- 支持预设的取消、重新打开和关闭实验，统计线程 ID、句柄、缓冲区、队列与耗时。
- 独立导出任务在原文副本会话添加固定内容，写入新 PDF；原文件前后散列保持一致。

**`phase0_quick_probe`，最小 Qt Quick 入口**：

- 先显示窗口与响应计数，再异步打开测试文件；选择文件、切换单页、调整显示缩放只用于实验。
- 使用真实后台位图与纹理节点显示；现有纹理随缩放立即变化，高清结果异步替换。
- 提供可关闭的统计层：实际 graphics API、DPR、请求序号、CPU 缓存及受管纹理估算；不做正式工具栏。
- 以简短固定交互轨迹切换页面/缩放/关闭文档，验证旧会话结果拒绝、资源回收和窗口重建。
- 附加最小 QML 文本编辑实验，验证中文 IME 的 preedit/commit 与焦点；这不等于阶段 5 标注产品已实现。

**建议实验顺序**：小文本 PDF 正确性 → 色彩/alpha/旋转样本 → 单页大扫描 → 数百 MB / GB 扫描教材 → 取消与关闭 → 中英文字和路径导出 → 快照故障 → 两平台重放。样本和计时方法遵循性能文档。

**预期产物**：可构建源码、固定依赖清单、最小编译说明、原型运行日志、实际输出图像/PDF、原始性能数据、许可证证据与阶段报告。大型本地 PDF 和测试者隐私数据不提交仓库。

**测试方式**：CTest 中注册坐标与线程契约测试；真实 PDF 集成测试；小型 color/alpha 金图与允许误差；两平台 GPU 交互检查；至少 30 次打开/关闭循环、100 次请求替换，另执行性能文档规定的重复测量。循环次数是实验计划，不是已通过结果。

**验收标准**：

1. Windows x64 和 macOS arm64 均有真实编译、链接与启动记录；实际后端分别为 D3D11 / Metal，CI 离屏测试不能代替这一条。
2. 真实 PDF 首屏来自 worker 渲染，无 UI PDFium 调用；所有调用和原生析构线程检查通过。
3. 色卡/透明/旋转/高 DPI 样本无通道错误或悬空缓冲；窗口隐藏重显和场景图重建后可恢复画面。
4. 坐标满足架构规定误差，输出 PDF 中的文字与笔迹在两个独立查看器位置正确，中英文字可提取，字体授权可追溯。
5. 大文件首屏、高清、CPU 内存、GPU 估算和取消延迟有原始数据；不要求此阶段达到最终启动/FPS 目标，但必须能定位超限路径。
6. 关闭后不接受旧会话图像，无未释放的应用自有句柄；超长调用及引擎内部内存限制如实记录。
7. 许可审查形成可执行的分发方案；没有关键未解决授权问题。仅有来源链接而未核对实际产物不算通过。
8. 原始 PDF 未改变；快照中断后至少保留前一有效修订；失败不会被标成保存成功。

**停止条件**：缺少平台、导出字体不正确、许可路径不明确、线程/资源错误或构建失败时，报告阶段 0 未完成和具体阻断。不能以“以后再优化”绕过前置正确性风险；参数优化不足可记录为后续项。

## 4. 阶段 1：最小桌面应用与启动

**目标**：形成可交互的正式应用外壳，建立低开销启动路径。

**依赖条件**：阶段 0 关键门槛通过，用户明确允许进入后续阶段。

**具体任务**：

- 将验证可复用的 adapter/构建配置整理入正式目录，保留原型证据。

  本次复用固定 Qt/C++20/警告配置；adapter 迁移延至阶段 2 的正式文档服务接口设计，因现有 adapter 混合了实验调度/固定导出，提前迁移会固化原型边界。阶段 1 正式目标完全不依赖 PDFium，原型通过 `LANGLERN_BUILD_PHASE0` 保留。
- 建立应用入口、窗口、轻量工具区、空文档状态、主题 token 和基本快捷键表。
- 集成系统文件选择；初期可明确提示尚未实现文档显示，不用假页面冒充已打开 PDF。
- 首窗前不扫描字体、不预热整本 PDF、不构建无用缓存；耗时服务按需启动。
- 加入启动里程碑与环境日志，建立 Windows/macOS CI 的构建和基本测试入口。

**预期产物**：可独立启动的应用、README、已验证编译命令、启动 trace 与 CI 配置。

**测试方式**：全新构建启动、文件对话框、主题/DPI、窗口与平台快捷键检查；冷/热启动按性能方案测量。

**验收标准**：两平台窗口实际可操作；启动前没有 PDF 解码；无文档空闲无应用自建持续轮询；所有启动数据带构建类型。记录距 300/800 ms 目标差距，超标需有归因与任务，不能宣称达标。

## 5. 阶段 2：文档会话与异步单页

Windows 已交付，实际证据、限制与 macOS 延期见 [PHASE2_REPORT.md](PHASE2_REPORT.md)。

**目标**：真实打开、显示、切换和关闭本地 PDF，建立可复用的异步接口。

**依赖条件**：阶段 1；阶段 0 已验证的字体/导出方案保留，不要求此时完成产品导出。

**具体任务**：

- 实现 Document Manager 状态、会话 ID、错误分类和 worker 生命周期。
- 首先读取所需页信息，显示预览，再替换目标清晰度；所有像素缓冲有所有权和分配上限。
- 完成 PageItem 场景图显示与资源失效恢复，基础页码导航和适应页宽。
- 验证路径编码、只读文件、受密码保护/损坏文件的明确失败反馈；不静默显示空白。
- 切换和关闭时取消排队任务、拒绝旧会话结果。

**预期产物**：可显示真实单页的应用、真实引擎集成测试、文件与页面事件日志。

**测试方式**：文本/扫描/旋转 PDF、中文路径；交错打开 A/B、关闭时在途渲染；原文件散列检查。

**验收标准**：正确页码和页面；PDFium 线程检查通过；UI 不同步等待 PDF；文档切换无旧页闪回；失败可诊断；50 次打开/关闭后应用自有句柄计数归零，内存测量区分缓存高水位和泄漏。

## 6. 阶段 3：连续布局、虚拟滚动和缓存

**目标**：使长文档滚动和缩放保持即时反馈，资源占用受控。

**依赖条件**：阶段 2 的几何快照、PageItem、会话失效及像素所有权。

**具体任务**：

- 建立变尺寸页面几何索引、渐进元信息、可见范围计算和锚点保持。
- 只实例化视口和受控邻域，支持长距离导航、滚轮和触控板。
- 调度可见预览/高清/预加载，限制队列、去重与结果背压。
- 实现 CPU/GPU 预算化缓存、pin 计费、在途预留、纹理上传限额和统计。
- 按证据实现大页分块或动态分辨率，验证接缝和单纹理尺寸限制。
- 统一配置分块、档位、预加载、内存预算和渐进时间片，不增加 PDFium 并发线程。

**预期产物**：连续阅读版本、调度/缓存/布局测试、大文件 trace、初始默认参数说明。

**测试方式**：持续滚动、快速反向、随机跳页、锚点缩放、低预算、高 DPI、窗口重建、30 分钟压力轨迹。

**验收标准**：不整本渲染或创建页面节点；应用可控驻留符合配置预算；可见工作优先且队列有界；缩放先复用纹理；旧请求不覆盖当前内容。按 60 Hz 目标记录 P95/P99 与首页/高清耗时，预算或帧时间未达标必须有可复现实验及解决任务，性能门槛详见性能文档。

## 7. 阶段 4：原生文字选择和复制

**目标**：在真实文字层上流畅选择、跨行/跨页复制，扫描页行为诚实明确。

**依赖条件**：阶段 3 的坐标、虚拟化和异步服务。

**具体任务**：

- worker 按需提取文本和字符框，建立字符串与字符索引映射。
- 实现命中、拖动扩选、跨页边缘滚动、平台剪贴板与选择高亮。
- 文本快照纳入预算，选择范围跨出可见区时按需提取，不持有整本原生文本句柄。
- 在 CropBox、旋转、高 DPI、中英混排和无文字层上定义明确行为。

**预期产物**：选择/复制功能、确定性文字 fixtures、索引/几何测试、已知复杂排版限制。

**测试方式**：跨行跨页、连字/组合字符/代理对、裁剪区外文字、空白、扫描页、鼠标和触控板并用。

**验收标准**：标准样本复制内容与预期一致，选择高亮误差不超过 1 设备像素舍入；无文字层不生成伪文本；选择不重新解码底图；剪贴板和 UI 不等待引擎长调用。

## 8. 阶段 5：文字答案与页面坐标

**目标**：空白单击即可输入答案，答案随页面准确变换。

**依赖条件**：阶段 3 页面变换、阶段 4 文字命中、阶段 0 字体/导出验证。

**具体任务**：

- 建立带稳定 ID 的标注模型、文字样式、页面单位和历史命令基础。
- 完成创建、编辑、移动、删除；未选中透明无边框，编辑器数量随可见/活跃范围控制。
- 实现 IME 预编辑与提交事务，焦点、文本局部撤销、全局历史的边界。
- 固定共享排版契约、命中优先级、输入/选择切换和平台快捷键。
- 加入纯数据标注快照接口，便于阶段 7 接入，不提前宣称已自动保存。

**预期产物**：文字练习版本、坐标/标注模型测试、IME 与排版检查记录。

**测试方式**：中英输入、组合字符、粘贴、多行、拖动、跨屏 DPR、旋转/裁剪/单位样本、撤销恢复。

**验收标准**：创建后直接输入；移动、缩放和调整窗口不漂移；坐标误差满足架构标准；预编辑不被保存或重复入历史；编辑输入不触发 PDF 渲染；文字选择和单击输入无冲突。

## 9. 阶段 6：画笔、擦除和撤销重做

**目标**：低延迟手写与标记，所有标注操作可预测地撤销恢复。

**依赖条件**：阶段 5 坐标、标注模型、命令历史和输入路由。

**具体任务**：

- 采样页面空间笔迹，支持多色与粗细；鼠标和触控笔路径共用数据模型。
- 实现活跃笔迹局部增量显示，完成后转为稳定几何；压力感应非 MVP 验收前提。
- 实现整条笔迹橡皮擦，命中容差由逻辑像素正确换算；一次手势合为一条命令。
- 统一文字/笔迹创建、移动、删除及擦除的历史，限制历史内存。
- 正确处理取消、离开窗口、工具切换与撤销后的 redo 分支失效。

**预期产物**：完整基础标注版本、命令与命中测试、长笔迹性能 trace。

**测试方式**：快速书写、长笔迹、大量历史、缩放擦除、焦点丢失、50 次混合 undo/redo 往返。

**验收标准**：颜色/粗细和位置一致；撤销往返恢复相同模型修订内容；取消不遗留半条标注；历史淘汰不删除当前模型；手写不触发底图解码；输入延迟与峰值内存按性能文档记录。

## 10. 阶段 7：自动保存、恢复和 PDF 导出

**目标**：练习可持续保存，重新打开可恢复，并可可靠交付新 PDF。

**依赖条件**：阶段 5/6 稳定快照与排版契约、阶段 0 字体和写入可行性。

**具体任务**：

- 实现工作区、身份校验、schema 版本和异步快照保存，状态显示与修订对应。
- 实现去抖/最长间隔、临时文件原子提交、备份及异常恢复，不静默覆盖损坏/未来版本。
- 处理原文件移动、内容改变、只读目录、磁盘满和多个写入者冲突；单窗口仍需工作区锁或明确冲突策略。
- 以独立 PDF 会话导出快照，嵌入已审查字体，写入文字/路径，保留原文；拒绝原文件别名目标。
- 提供导出进度、失败反馈和修订标识；独占调用期间界面继续响应。

**预期产物**：持久化格式说明、恢复与导出功能、故障注入报告、可独立查看的真实输出 PDF。

**测试方式**：重新启动、写入各阶段强制结束、旧/新 schema、权限/空间失败、原文件修改、目标硬链接、导出期间编辑；至少两个独立查看器及提取结果比较。

**验收标准**：正常关闭后已提交内容恢复；异常恢复到最后成功落盘修订，不能声称零丢失；坏快照可回退且保留证据；写失败不显示成功；原文件散列不变；新增文字可提取且位置/字体正确，笔迹颜色/粗细/透明度准确；未修改页没有不必要栅格化。

## 11. 阶段 8：交互、性能与跨平台发行验收

**目标**：完成可公开交付的 MVP，验证真实学习流程与资源消耗。

**依赖条件**：阶段 0–7 功能与正确性门槛完成，无阻断数据安全问题。

**具体任务**：

- 调整快捷键、工具状态、浅/深色、高 DPI、焦点与可访问性；保持轻量视觉。
- 在参考设备上完成全部标准轨迹，按证据调整缓存/档位/预加载，消除主要启动与帧时间瓶颈。
- Windows/macOS CI 构建与自动测试，干净系统验证 Qt 动态库、QML 插件、PDFium 与字体部署。
- 完成打包和卸载/更新数据保留说明；macOS 签名、公证等按实际发行渠道和凭据条件验证。
- 更新 README、编译说明、贡献指南、项目 LICENSE 和第三方通知，核对实际包内容与许可清单。

**预期产物**：两平台发行候选包、完整性能报告、CI 证据、安装检查与已知限制。

**测试方式**：离线干净系统安装，完整阅读练习保存导出流程；60 Hz / 高刷新率轨迹；30 分钟压力和恢复测试；逐包授权清点。

**验收标准**：所有 MVP 功能有真实验收证据；性能门槛与预算按测试设备报告，无伪造达标；离线可用；两平台核心数据一致；发行包许可义务已处理。签名/公证或平台性能未验证时明确标记候选包限制，不称正式双平台验收完成。

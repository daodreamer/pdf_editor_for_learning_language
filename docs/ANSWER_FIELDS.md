# 横线填写与删减后自适应（2026-10-17）

后续已支持规则点状和短划虚线，并以用户指定的真实教材完成本机验收，见 [DASHED_LINES.md](DASHED_LINES.md)。下文保留最初实线版本的验证记录；后续本机测试样本以 AGENTS.md 的固定教材要求为准。

## 使用与实现

自动或打字模式下，鼠标移到检测出的空白横线上方，会显示浅蓝色填写区域；点击即创建并聚焦现有 `TextNote` / `TextEdit`。没有另建编辑器，格式浮窗、IME、移动/缩放、撤销重做、自动保存及导出继续走原有路径。已有文字答案优先，不在同一横线上重复创建。书写、橡皮、原文选择、批改、点读模式不显示横线提示。

初始框宽匹配横线；输入后按当前文字自然宽度调整，以横线长度为换行上限。多行/页面边缘不再让自动框永久锁宽。删除文字时同时重新计算宽度与行高；旧版自动锁宽或手动放大的框在删减后也会收缩，原宽度保留为换行上限。清空后保留小的可编辑空框，结束编辑时按原规则删除空答案。字号/格式参与测量，输入法组合宽度同样受横线和页面边界限制。

HTML 原型通过 `data-blank` 标记预先定义空白。本实现读取真实 PDF，没有预设练习题坐标：PDFium 工作线程复用页面渲染图像，以最多 1024×2048 像素检测薄水平实线及上方空白，每页最多 128 个候选；排除已有文字下划线、宽色块及明显表格交点。候选随页面 CPU 图像缓存保存、淘汰，坐标随 CropBox/旋转/缩放/双页转换，容量计入 CPU 缓存统计。未增加 OCR、额外页面解码、第三方库或网络依赖。

这属于启发式检测，不能保证理解教材语义。倾斜、模糊/低对比度横线、不规则长间隙及复杂表格可能漏检或误判；未识别处继续使用原有的空白点击输入。当前没有用真实教材全集计算准确率。

## 实际验证

Windows 11 x64，Intel Core Ultra 7 265K / RTX 5070 / D3D11，Qt 6.8.3、PDFium 157.0.8100.0、MSVC x64 Release。构建及 qmllint 无警告；最终 CTest **8/8** 组通过（57.83 s），文字标注 **13** 项通过。大文件与长压力 opt-in 用例按原规则跳过。macOS、物理数位笔、物理跨屏及 sanitizer 本轮未执行。

真实窗口覆盖：

- 矢量、CropBox、90° 旋转和合成扫描图页面的检测，排除文字下划线/表格。
- 离开活跃范围再返回仍缓存的页面，悬停提示仍可用。
- 悬停、点击创建、自动聚焦、长文本换行、选择一部分删除后宽/高收缩、全部清空及局部撤销重做。
- 手动调整、已有文本框的悬停/角点、中文 IME、格式浮窗、整框历史和已有笔迹输入回归。
- 新字段快照编解码及真实自动保存、关闭、重开恢复。输入/删除过程中 PDF 渲染任务数保持不变。
- `QT_SCALE_FACTOR=2` 的附加高 DPI 回归通过（模拟缩放，不等于物理跨屏验证）。

证据：`benchmarks/results/answer-fields-20261017/`，包括普通/DPI 截图、测试与构建日志、实际 `answer-export.pdf`、MuPDF 独立回读及渲染图。生成样例为自制 MIT 测试数据，生成器 `tools/make-answer-fixture.py`，不能冒充真实教材。独立回读确认 `short` 位于横线上方，4 页裁剪/旋转保留、其他 3 页像素不变、源文件 SHA-256 未变。

## 回放比较

比较基线 `benchmarks/results/ink-smooth-after-20261017/` 与本轮 `benchmarks/results/answer-fields-ink-20261017-verified/`。逐文件核对基线源码 SHA-256 与本轮修改前提交 `eabaceeec3ae101dbd34cf483b146a3e2cc61c3d` 一致。两组同设备/样本/Release/DPR 1.5，每组 3 轮、每轮 8192 次合成移动事件，存储 7766 点；完整原始事件、帧间隔和输入/二进制/源码散列保留。

以下为三轮各自分位数的中位数，不是合并原始帧后的分位数：

| 指标（ms） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 事件处理 P95 | 0.0032 | 0.0032 |
| 事件处理 P99 | 0.0378 | 0.0489 |
| Qt 帧间隔 P95 | 19.5236 | 19.6696 |
| Qt 帧间隔 P99 | 21.0951 | 22.7001 |

P95 接近，P99 有上升，三轮不足以确认长期性能变化；不宣称帧率或硬件输入延迟提升。Qt `frameSwapped` 为提交代理，不是硬件显示时刻。首轮独立长笔迹回放出现未提交手势，按失败保留在 `answer-fields-ink-20261017/`，未生成有效性能指标；其具体中断来源未确认，不纳入上表。随后三轮有效回放及完整笔迹回归通过。合成检测样例单次检测约 2.4 ms，仅为诊断数据，不是大型教材首屏时延验收。

CPU 缓存统计现在包含横线候选容量，GPU 统计仍只计页面纹理。未采样系统 GPU 显存，未执行新的长期阅读压力。

## 2026-11-10 多行填写线作为一个整体答案

**行为**：几条连续的填写线视为一个答案块。悬停块内任意一行，提示框覆盖整块；点击后创建一个文字答案覆盖所有横线。输入到行尾自动换到下一条横线，按 Enter 也换到下一条横线；块内任意文本可像一个输入框一样选择、格式化、撤销，Ctrl+Delete 或右键擦除整体删除，删除后整块重新提示。

**分组规则**（`ShellState::answerBlockAt`，在悬停/点击时基于已检测的横线与当前页面图像计算，不改检测结果或缓存）：同一字段类型（高度一致）、左右端对齐（页宽 2% 内）、相邻间距 12–40 pt 且稳定（±20%）、均未被已有答案覆盖、两条横线之间没有印刷内容（排除“题目—横线—题目—横线”）。横线左侧紧邻印刷标号（“1”“a)”“Nom :”）的行开始新的题目，因此编号单行题各自独立；标号判定要求墨迹只在该行文字带内，旁边插图不算标号。

**排版**：新增可选字段 `notes.lineSpacing`（PDF 单位，旧文件为 0），见 [STORAGE_FORMAT.md](STORAGE_FORMAT.md)。首行与单行答案位置相同（基线在横线上方约 0.6 pt），其余行间距按字体实际行距补足到横线行距（`QTextBlockFormat::LineDistanceHeight`），由 `applyLineSpacing` 在编辑器、尺寸计算和 PDF 导出三处共用。FixedHeight 方案实测会把多余空间放在文字上方，使每行落在横线下约 5 pt，已弃用。块答案删减文字时保持整块高度。

**验证**：`realWorkbookRuledBlockAnswer`（练习册 3 第 14 页）：7 行块识别、行距 20.10 pt；编辑器各行间距 20.09 pt；导出基线 10.44 / 30.53 / 50.63 pt，横线在 11 / 31.1 / 51.2 pt；存储往返一致；块内其他行不再单独提示；整体删除后提示恢复。页面截图逐像素核对文字底部位于横线上方 2–3 px。练习册 1、2、3 全书分组抽查：第 9 页三组 4 行、练习册 1 第 40 页每题 2 行、练习册 2 第 25 页每题 3 行均与版面一致；练习册 3 第 10 页“题目—横线”交替的练习不再被合并。

本轮完整 CTest 中 `text_selection`、`natural_speech` 两项失败：运行时前台为全屏游戏窗口，测试窗口无法成为活动窗口，依赖窗口激活的 Ctrl+C 快捷键与选区浮层无法触发；临时关闭提示计算的对照实验同样失败，确认与本改动无关，但未在无干扰时复跑，标记为未验证。其余 8 组通过，qmllint 通过。证据：`benchmarks/results/ruled-blocks-20261110/`。
